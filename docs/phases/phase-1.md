# المرحلة 1: Passthrough لعينين

**الحالة:** الأساس شغّال على الجهاز، **والبوابة لسا ما نعبرت** (ناقص reprojection للكاميرا وتجربة بالنظارة).

## شو انبنى

- **`:core:render`**
  - Pipeline بـ GL ES 3.0: صورة الكاميرا (OES) بحجمها الزاوي الحقيقي لكل عين، وبعدين pass للتشويه بـ mesh (شبكة 40×40، fetch وحدة لكل pixel).
  - نمط معايرة (شبكة، وصليب، ودائرة على 30°).
  - Eye buffers بحجم مرتبط بمستوى الجودة.
  - Choreographer driver للـ pacing تحت 60fps.
  - المعايرة محفوظة بـ DataStore.
- **منطق صافي عليه tests:** `DistortionModel` (مع inverse)، و`DistortionMeshBuilder`، و`EyeLayout`، و`FrameStatsTracker`، و`FramePacer`.
- **`:core:tracking`:** `ArCoreSessionManager` (`LATEST_CAMERA_IMAGE`، وplanes وlight وdepth مطفيين للحرارة) و`ArCoreCameraFrameSource`.
- **`:core:thermal`:** `PolicyThermalGovernor` مع hysteresis (بيطلع للأسخن فوراً، وبينزل درجة وحدة كل 30 ثانية)، وقراءات مشتركة بين كل المستمعين، وحرارة البطارية.
- **`:app`:**
  - شاشة passthrough مع overlay للمطوّر فوق كل عين.
  - شاشة معايرة: لوحة لمس برا النظارة، وأزرار الصوت ولمسة الشاشة جوّا النظارة.
  - `PerfRecorder` بيكتب CSV كل ثانية.
  - الشاشة مثبّتة على 60Hz، ووضع الأداء المستدام شغّال إذا الجهاز بيدعمه.

## القياسات (OPPO CPH2699، Snapdragon 6 Gen 1، Adreno 710)

**إعدادات الكاميرا اللي اختارها ARCore:** GPU 1920×1080، وCPU 640×480، و**30fps بس** (الجهاز ما بيعرض 60). مجال رؤية الكاميرا حوالي 65°×39° (half-tan 0.64×0.36).

**تجربة حوالي 14 دقيقة** (2026-11-24)، الموبايل بالإيد وعم يتحرّك، وموصول بـ USB وعم يشحن، **وبلّش وهو سخن** (جلد 42.7°):

| | القيمة |
| --- | --- |
| fps | متوسط **59.1**، بين 59.6 و59.9 بكل دقيقة، وأدنى قراءة 28.9 |
| p95 لوقت الفريم | 19.5–22.6 ms |
| «jank» (> 20ms) | حوالي 11%. **رقم مضلِّل:** الـ fps ما نزل، يعني ما في vsync ضايع. الحد صار 25ms (1.5 vsync) |
| عمر صورة الكاميرا | وسيط **92ms**، وp95 **136ms** |
| حالة الحرارة | `NONE` لحد الدقيقة 4، وبعدها `LIGHT` لآخر التجربة. headroom أقصى 0.68، والجودة ضلّت NORMAL |
| البطارية | 36° لـ 38° |
| التتبّع | 97% من الوقت |

## القرارات

| القرار | ليش |
| --- | --- |
| الـ shaders بـ Kotlin مش assets | الـ renderer ما بيحتاج Context، والكود بيضل جنب الكلاس اللي بيستعمله |
| Mesh distortion بشبكة منتظمة على الشاشة، وإحداثيات العين بالـ distort المباشر | ما بيحتاج inverse وقت الرسم، وتكلفته على الـ GPU قليلة |
| `eyeRenderScale` جوّا `QualityLevel` (0.85 / 0.75 / 0.65) | الجهاز متوسط |
| حد الـ jank 25ms بدل 20 | توقيت الـ callbacks بالـ CPU بيتذبذب بدون ما يضيع vsync |
| قراءات الحرارة مشتركة (`shareIn`) | الـ overlay والـ governor والـ CSV كانوا رح يسجّلوا 3 listeners |

## اللي اكتشفناه

1. **تأخير الكاميرا هو الخطر الأول على الراحة.** 30fps مع معالجة ARCore بيعطوا حوالي 90ms، وما في إعداد بيحلّها. **الحل اللي بقترحه:** reprojection للكاميرا. منلف صورة الكاميرا بفرق دوران الراس بين لحظة اللقط ولحظة العرض، من `TYPE_ROTATION_VECTOR` أو `GAME_ROTATION_VECTOR`. هيك الغرفة بتضل ثابتة بالدوران حتى لو الصورة متأخرة. كان مخطط للمرحلة 2، بس صار شرط لبوابة المرحلة 1.
2. **OPPO بتفلتر `Log.d` من الـ main thread:** سطور الـ GL والـ IO بتطلع، وسطور الـ main لأ. فلهيك المعلومات المهمة (إعدادات الكاميرا) بتنعرض بالـ overlay.
3. **Thermal status بيوصل `LIGHT` (جلد حوالي 50°) خلال 4 دقايق** إذا بلّش الموبايل سخن وعم يشحن. التجربة الجاية: موبايل بارد، ومش عالشاحن، وبالنظارة.
